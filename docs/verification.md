# 자세 감지 검증 기록

2026-11-14에 확인한 내용이다. "나쁜 자세를 실제로 잡아내는가"가 서비스의 핵심이라, 무엇이 확인됐고 무엇이 확인되지 않았는지를 나눠 적는다.

## 결론

| 항목 | 판정 | 근거 |
|---|---|---|
| 스쿼트 횟수 | 확인됨 | 일반인 20명의 영상 36개에서 180회 중 180회 감지 |
| 사람 인식 | 확인됨 | 24,865프레임 전부에서 관절을 찾음 |
| 깊이 부족 | 확인됨 | 20명 중 10명이 기준 미달. 4명의 최저점 장면을 눈으로 대조해 일치 |
| 상체 기울기 | 측정은 확인됨 | 5~50도 범위로 측정되고 같은 사람은 매회 비슷한 값 |
| 허리 숙이기 구분 | 측면만 확인됨 | 케틀벨 영상에서 실제 6회만 세고 숙이기 2번은 제외 |
| 세트 안의 변화 (깊이, 속도, 기울기) | 확인됨 | 같은 사람의 반복 간 값이 안정적이라 변화가 드러남 |
| 무릎 안쪽 모임 | **확인 못 함** | 데이터 80회 중 해당 사례가 0건 |
| 좌우 쏠림 | **확인 못 함** | 카메라가 비스듬한 영상에서 오탐 발생 |
| 실제 휴대폰 카메라 | **확인 못 함** | 영상 파일로만 시험함 |

말할 수 있는 것은 횟수, 깊이, 상체 기울기, 그리고 반복이 진행되며 무너지는 시점이다. 무릎 모임과 좌우 쏠림은 참고용 관찰로만 표현한다.

## 무엇으로 검증했나

**공개 데이터셋.** [Dual-View Squat Movement Dataset](https://github.com/nihar787airobotics/squat_dataset_publication)은 운동 경험이 없는 성인 20명(남 15, 여 5)이 맨몸 스쿼트를 5회씩 하는 모습을 정면과 측면에서 동시에 찍은 것이다. 한 영상의 정답 횟수가 5회로 정해져 있어 횟수 검증에 쓸 수 있다. 영상마다 MediaPipe Pose Landmarker Full로 뽑은 관절 좌표가 함께 들어 있다.

**검증 방법.** `pose-test.html`의 규칙을 그대로 옮긴 `tools/verify/replay.py`가 관절 좌표를 프레임 순서대로 읽어 같은 판정을 낸다. 측면 20개와 정면 16개를 돌렸다. 정면 4개(12, 17, 18, 19번)는 내려받기가 실패해 빠졌다.

**브라우저 실측.** 위키미디어 공용의 스쿼트 영상 3개를 시험 페이지에서 실제로 재생하며 추적했다. 브라우저는 lite 모델을 쓰므로 데이터셋의 Full 모델 결과와는 별개의 확인이다.

## 결과

| | 측면 | 정면 |
|---|---|---|
| 영상 수 | 20 | 16 |
| 정확히 5회로 센 영상 | 20 | 16 |
| 감지한 반복 | 100 / 100 | 80 / 80 |
| 최저점 엉덩이 높이 비율 | 0.30~0.70 | 0.44~0.77 |
| 한 번에 걸린 시간 | 0.9~2.7초 | 0.8~2.2초 |
| 상체 최대 기울기 | 5~50도 | 정면에서는 측정 불가 |
| 최저점 허벅지 각도 | -12~40도 | 정면에서는 측정 불가 |
| 무릎 간격 / 발목 간격 | 해당 없음 | 1.01~1.57 |
| 골반 쏠림 | 해당 없음 | 0.00~0.13 |

브라우저 실측에서는 50초짜리 측면 영상을 프레임당 중앙값 12ms(M4 맥북)로 처리했고 6회를 정확히 셌다.

**같은 사람의 값은 일정했다.** 예를 들어 1번 참가자의 허벅지 각도는 5회가 33, 40, 37, 36, 36도였고 14번 참가자는 -4, -9, -12, -10, -12도였다. 사람 사이의 차이(50도 범위)에 비해 한 사람 안의 흔들림이 작다. 그래서 "이 사람이 평소보다 얕게 앉았다"는 판단은 믿을 수 있다.

**눈으로 대조한 4명.** 허벅지 각도가 40도, 34도로 측정된 두 사람은 장면에서도 엉덩이가 무릎보다 확실히 높았고, 14도인 사람은 수평에 가까웠으며, -9도인 사람은 엉덩이가 무릎 아래로 내려가 있었다.

## 검증하다 찾은 버그

1. **허리 숙이기가 스쿼트로 세어졌다.** 케틀벨을 집고 내려놓는 동작 때문에 6회가 8회로 나왔다. 측면에서 상체가 65도 넘게 기울고 허벅지가 서 있으면 버리도록 고쳤다. 실제 스쿼트 100회의 상체 기울기 최댓값이 50도라서 정상 동작은 걸리지 않는다.
2. **정면 영상에서 실제 스쿼트를 버렸다.** 몸통이 짧아 보이는 정도로 숙이기를 가리려 했더니 80회 중 7회를 버렸다. 정면에서는 이 규칙을 없앴다. 그래서 정면 촬영에서는 허리 숙이기를 걸러내지 못한다.

## 논문이 말하는 한계

- MediaPipe BlazePose의 무릎 각도는 정지 자세에서 RMSE 약 15도이고, 얕게 굽힐 때는 크게, 깊게 굽힐 때는 작게 나온다 ([JMIR 사전 공개 논문](https://pmc.ncbi.nlm.nih.gov/articles/PMC13730411)). 절대 각도를 기준으로 삼기 어렵다는 뜻이다. 우리가 무릎 각도 대신 엉덩이 높이 비율과 반복 간 변화를 쓰는 이유다.
- 무릎이 안으로 모이는 각도는 MediaPipe가 3D 장비(Vicon)보다 약 19도 크게 잰 연구가 있다 ([Heliyon](https://www.cell.com/heliyon/fulltext/S2405-8440(24)12369-9)).
- 2D 영상의 무릎 정면 각도는 3D와의 상관이 연구마다 0.64~0.78에서 0~0.57까지 갈린다 ([PMC5808017](https://pmc.ncbi.nlm.nih.gov/articles/PMC5808017)).
- 카메라 한 대로 한쪽 다리 스쿼트의 오류를 분류했을 때 전문가 판정과의 일치율은 53~77%였고, 무릎 모임이 77%로 가장 높았다 ([JMIR 계열 연구](https://www.sciencedirect.com/org/science/article/pii/S2291522226000549)).
- 비전 언어 모델이 운동 영상을 보고 직접 자세를 교정하게 하면 정확도가 44~58%이고 없는 문제를 지적하는 비율이 74~97%였다 ([FormCoach](https://arxiv.org/html/2508.07501v1)). 2026년 4월 연구에서도 최신 모델이 무작위보다 조금 나은 수준이었다 ([arXiv 2604.08294](https://arxiv.org/abs/2604.08294)).

그래서 이 서비스에서 AI는 자세를 판단하지 않는다. 판단은 관절 추적과 계산이 하고, AI는 그 수치를 문장으로 옮긴다.

## 다시 돌려 보는 법

```bash
sh tools/verify/fetch.sh /tmp/squat-keypoints          # 관절 좌표 40개를 받아 필요한 관절만 남긴다 (약 32MB)
python3 tools/verify/replay.py /tmp/squat-keypoints > /tmp/results.json
```

진행 상황은 표준 에러로, 영상별 반복 수치는 JSON으로 나온다. `pose-test.html`의 기준값을 바꾸면 `replay.py`의 같은 값도 바꿔서 다시 돌린다.

## 남은 확인

- 휴대폰 실기기에서의 속도와 인식률
- 뒤에 사람이 지나가는 환경에서 추적이 다른 사람으로 넘어가는지
- 무릎 모임 사례가 들어 있는 데이터로 정면 규칙 검증 (EJUST-SQUAT-21, Waseda Squat 데이터셋이 후보다)
- 내려받지 못한 정면 영상 4개
