# 기획 요구사항과 구현 대조

2026-11-14 12시 30분 기준이다. 기획 문서, 피그마의 와이어프레임, 심사 기준표를 구현과 하나씩 대조했다.

## 서비스 정의 (피그마 기획 슬라이드)

> MUSCLE MAP. 내 몸의 숨겨진 운동 패턴을 발견하고, 나에게 맞는 운동 방향을 찾아주는 것

문제 정의의 핵심 문장은 "반복 횟수가 증가하면서 나타나는 동작 범위의 감소나 움직임의 불균형은 스스로 인지하기 어렵다"이다. 구현의 중심도 여기에 맞췄다. 세트를 저장하면 서버가 **몇 회째부터 깊이나 속도가 무너졌는지**를 계산한다.

## MVP 화면 5단계

| 단계 | 와이어프레임의 요구 | 구현 | 상태 |
|---|---|---|---|
| 01 BODY PROFILE (인바디 분석) | 결과지 업로드와 자동 추출, 체중, 골격근량, 체지방률, BMI, 부위별 근육량, 가상 데이터 표시 | `POST /api/inbody`. 가상 데이터(`sample`), 직접 입력, 사진 읽기. 좌우 차이 계산 | 동작. 사진 읽기는 실제 결과지로 미검증이라 시연은 가상 데이터 |
| 02 BODY CHECK (사용자 문진) | 앉아 있는 시간, 주당 운동 횟수, 불편한 부위, 신체 사용 습관, 운동 목표 | `POST /api/surveys`. 다섯 항목 모두 저장 | 동작 |
| 03 BODY ALERT (발생 가능 문제 제안) | 인바디와 문진을 종합한 사전 분석. 관찰 영역, 상태 표시(추가 확인 권장, 측정 필요), 확인하면 좋은 패턴, 다음 단계 안내 | `POST /api/body-alerts/analyze`. 영역마다 부위, 좌우, 상태, 근거, 확인 패턴 반환 | 동작. 3D 바디맵은 없고 부위 이름을 돌려주므로 프론트가 그림에 표시 |
| 04 AI 카메라 인식 | 카메라 촬영, 진행 표시, 음성 코칭 | 브라우저에서 MediaPipe로 실시간 추적. 횟수, 깊이, 상체 기울기, 음성 안내 | 동작. 영상으로 검증했고 휴대폰 실기기는 미검증 |
| 05 결과 (카메라 인식 후 자세 제안) | 아래 표 | `POST /api/sets`, `POST /api/sets/{id}/feedback` | 아래 표 |

### 05 결과 화면의 요소

| 요소 | 요구 | 구현 | 상태 |
|---|---|---|---|
| 종합 분석 | 개인별 신체 상태 요약 | `feedback.summary`. 이전 세트와의 비교 포함 | 동작 |
| 자세 시각화 | AI 관절 스켈레톤 분석 | 카메라 화면에 관절을 겹쳐 그림 | 촬영 중에만 보임. 결과 화면용 정지 이미지는 없음 |
| 주요 관찰 결과 | 어깨, 골반, 무릎, 발목 등 | 깊이, 상체 기울기, 무릎 간격, 골반 쏠림 | 부분. 어깨와 발목은 재지 않음. 무릎과 골반은 미검증 |
| 인바디 연계 | 부위별 근육량과 움직임의 관계 | AI 설명과 패턴 분석이 인바디를 함께 봄 | 동작 |
| 불편함 관련 정보 | 주의할 움직임 및 부담 요인 | `observations[].possibleLoad`. 가능성으로만 표현 | 동작 |
| 맞춤 운동 | 개인별 교정 운동 | `feedback.exercises`. 이름, 이유, 방법 | 동작 |
| 운동 가이드 | 동작 이미지 및 영상 | 없음 | **미구현**. 방법은 글로만 제공 |
| 재측정 목표 | 다음 측정 시 확인할 변화 | `feedback.retestGoals`. 수치 목표 | 동작 |

## 개발팀 기능 표

| 기능 | 상태 | 비고 |
|---|---|---|
| 카메라 연동 | 동작 | HTTPS 필요 |
| 자세 분석 (MediaPipe) | 동작 | 20명 180회 검증 |
| 운동 횟수 | 동작 | 180회 중 180회 |
| EMG 데이터 | 가상 데이터만 | 실제 센서 없음 |
| 신호 분석 (필터링, RMS) | **미구현** | 가상 값을 반복별 요약으로만 받는다. 원신호를 다루지 않아 필터링할 대상이 없다 |
| 데이터 시각화 (근육 활성 그래프) | 수치만 | 좌우 차이와 목표 근육 비중을 숫자로 제공. 그래프는 프론트 몫 |
| AI 피드백 | 동작 | 수치를 문장으로 옮김 |
| 누적 데이터 | 동작 | 서버가 재시작하면 초기화되고 시드만 남음 |

## 다섯 가지 질문

| 질문 | 답 |
|---|---|
| 실제 sEMG 센서를 연결할 수 있는가 | 오늘은 못 했다. 시판 센서로 가능하고 웹에서는 안드로이드와 PC 크롬만 된다 |
| 가상 데이터를 활용할 수 있는가 | 했다. 시뮬레이션이라고 표시한다 |
| 스쿼트 반복 구간을 인식할 수 있는가 | 했다. 엉덩이 높이 비율로 센다 |
| EMG와 영상을 동기화할 수 있는가 | 가상 값은 영상에서 만들므로 처음부터 맞는다. 실제 센서는 지연 보정이 남는다 |
| 실시간으로 표현할 수 있는가 | 했다. 추적과 음성은 즉시, AI 설명은 세트 뒤 10~20초 |

## 기획과 달라진 점

발표에서 먼저 말해 두는 편이 좋은 것들이다.

1. **근육 활성은 측정이 아니라 시뮬레이션이다.** 기획의 첫 차별점이 "실제 근육 활성 반응 분석"이지만 센서가 없다. 피그마 슬라이드의 문제 정의도 "아직 웨어러블 서비스에 적용한 게 아니기 때문에"라고 범위를 좁혔다
2. **무릎 정렬과 좌우 쏠림은 참고용이다.** 양성 사례를 구하지 못해 기준값을 검증하지 못했다. 대신 세트 안에서 무릎 간격이 좁아지는 변화를 잰다
3. **자세의 절대 평가가 아니라 변화를 본다.** 관절 추적의 각도 오차 때문이다. "자세 점수 79점" 같은 절대 점수는 내지 않는다
4. **인바디는 가상 데이터로 시연한다**
